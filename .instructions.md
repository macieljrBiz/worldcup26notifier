# WorldCupNotifier Development Instructions

## Project Overview
A native Windows WPF/XAML desktop application that monitors FIFA World Cup matches via the football-data.org API and sends Windows native toast notifications for kickoff, goals, and final results.

**Technology Stack**: .NET 8.0 WPF, C#, XAML, Windows 10.0.19041.0+

## Key Architectural Patterns

### 1. Configuration & Persistence
- Settings stored as JSON in `%APPDATA%\WorldCupNotifier\settings.json`
- Loaded on startup via `LoadSettings()`
- Saved explicitly when user clicks "Save settings" button
- Settings class: `AppSettings` (sealed, public properties with defaults)

### 2. Event Detection & Deduplication
- **Polling Loop**: `DispatcherTimer` (WPF UI-friendly async timer)
- **Snapshots**: `MatchSnapshot` records capture match state (Id, Status, HomeScore, AwayScore)
- **Event Types**:
  - Kickoff: Match starting in 15-min window or status change to LIVE/IN_PLAY/PAUSED
  - Goals: Score increase detected in snapshot comparison
  - Results: Status transitions to FINISHED
- **Deduplication**: `HashSet<string> _sentEventIds` tracks delivered event IDs to prevent duplicate notifications

### 3. API Integration
- **Service**: football-data.org (REST + JSON)
- **Rate Limiting**: 10 calls/minute enforced via minimum 70-second polling interval
- **Date Range**: Queries matches from yesterday to +14 days
- **Auth**: X-Auth-Token header with user-provided API key
- **Models**: JSON-annotated records (FootballDataResponse, Match, Team, Score, ScorePart)

### 4. UI Layout
- **Left Panel**: Configuration controls (API key, team selection, alert filters, polling settings)
- **Top Right**: Status display (current state, last check details)
- **Right Panel**: Alert feed (scrollable, up to 50 items, most recent first)
- **Styling**: Fluent-inspired design, light background (#F4F7FB), white cards, blue accents (#0067B8)

### 5. Windows Integration
- **Toast Notifications**: `DesktopNotificationService` (static methods)
- **COM Interop**: IShellLinkW, IPersistFile, IPropertyStore for Start Menu shortcut
- **AppUserModelID**: Registers app with Windows notification system (enables toast delivery)

## Code Conventions & Style

### Naming & Organization
- Namespace: `WorldCupNotifier`
- Classes: PascalCase (MainWindow, AppSettings, DesktopNotificationService)
- Private fields: `_camelCase` with underscore prefix
- Public properties: PascalCase
- Event handlers: `ControlName_Action` (e.g., `SaveButton_Click`, `CheckNowButton_Click`)

### C# Best Practices
- Enable nullable reference types (`<Nullable>enable</Nullable>`)
- Enable implicit usings (`<ImplicitUsings>enable</ImplicitUsings>`)
- Use sealed classes for records and internal data types
- Use records (sealed record) for immutable data structures (AlertItem, DetectedEvent, MatchSnapshot)
- Use target-typed new expressions
- Prefer expression-bodied methods where readable
- Add XML doc comments for public API (optional for internal code)

### XAML Conventions
- NamedElements: `x:Name` for controls accessed in code-behind
- Binding: Use `{Binding PropertyName}` for ObservableCollection items
- Styling: Inline background/foreground colors, CornerRadius for rounded corners
- Spacing: Margin and Padding for consistent whitespace (typically 6, 8, 12, 16, 18, 24)
- Colors:
  - Background: #F4F7FB (light gray)
  - Cards: White
  - Primary accent: #0067B8 (blue)
  - Text primary: #172033 (dark gray)
  - Text secondary: #61708A (muted gray)
  - Borders: #D8E0EC (light border)

### Async Patterns
- Use `async Task` for event handlers calling async methods
- Use `await` consistently for HttpClient calls
- Disable UI controls during async operations (CheckNowButton.IsEnabled = false)
- Always re-enable controls in finally blocks

### Error Handling
- Wrap API calls in try-catch (specific exceptions for football-data.org errors)
- Log all errors to feed via `AddFeedItem()` for user visibility
- Status updates on error via `SetStatus()`
- User-friendly error messages (avoid technical jargon)

### Key Entry Points
1. **App.xaml.cs OnStartup()**: Initializes DesktopNotificationService
2. **MainWindow Constructor**: Loads settings, populates team dropdown, sets up polling timer
3. **CheckLiveDataAsync()**: Main polling loop, calls football-data.org and triggers event detection
4. **DetectEvents()**: Compares snapshots and generates DetectedEvent list

### Testing Notifications
- Click "Send test notification" button in Configuration panel
- Verify native Windows toast appears
- Check feed for confirmation message

### Settings Management
1. User modifies UI controls (API key, team, checkboxes, polling interval)
2. Click "Save settings" button
3. SaveSettings() updates AppSettings object and persists to JSON
4. ApplySettingsToUi() reflects changes back to controls

## Common Tasks & Patterns

### Adding a New Alert Type
1. Add checkbox to XAML (Configuration panel)
2. Add property to AppSettings class (bool NotifyX)
3. Add load/save logic in LoadSettings() / SaveSettings()
4. Add UI application logic in ApplySettingsToUi()
5. Add detection logic in new DetectXEvents() method
6. Call from DetectEvents() foreach loop

### Modifying UI Layout
- Adjust Grid RowDefinitions/ColumnDefinitions
- Update Border Padding, Margin, CornerRadius
- Maintain color scheme and spacing conventions
- Test responsive behavior (MinHeight, MinWidth on main Window)

### Changing Polling Behavior
- Modify PollingIntervalSeconds validation (currently min 70)
- Update DispatcherTimer.Interval in ApplySettingsToUi()
- Respect API rate limits (10 calls/minute = min 6 seconds, but 70 recommended)
- Consider UX impact of very short/long intervals

### Extending API Integration
- Add new models if football-data.org response structure changes
- Update JSON deserialization in FetchMatchesAsync()
- Add new date range queries or filters as needed
- Always handle missing/null properties gracefully

## Important Constraints & Limitations

### Platform Dependencies
- **Windows Only**: Toast notifications, COM interop, Start Menu shortcut
- **No Cross-Platform Support**: DesktopNotificationService throws InvalidOperationException on non-Windows
- Gracefully handles initialization failures (try-catch in App.xaml.cs OnStartup)

### API Limitations
- **Rate Limit**: 10 calls/minute (enforced via 70-second minimum interval)
- **Data Availability**: Matches only available for valid competitions (default: "WC" for World Cup)
- **Real-Time Gaps**: No intra-match play-by-play data; goals/status detected only at polling intervals
- **Authentication**: Requires valid football-data.org API key

### UI Constraints
- **Feed Limit**: Stores only 50 most recent alerts (older items auto-removed)
- **Deduplication**: Event IDs prevent duplicate notifications (must clear HashSet on app restart for testing)
- **Team Selection**: Populated from API response + user input (fallback team list in MainWindow)
