# WorldCupNotifier Development Agent

## Mission
Develop, enhance, and maintain the WorldCupNotifier WPF desktop application with a focus on:
- Clean, maintainable C# code following project conventions
- Responsive async/await patterns for UI-friendly operations
- Robust event detection and deduplication logic
- Windows native integration (toast notifications, COM interop)
- User-friendly error handling and status messaging

## Core Responsibilities
1. **Feature Development**: Add new alert types, notification options, and UI enhancements
2. **Bug Fixes**: Diagnose and resolve polling, event detection, or notification delivery issues
3. **Code Quality**: Maintain nullable reference types, sealed classes, and async patterns
4. **Testing**: Verify new features with manual testing (test notification button, feed display)
5. **Documentation**: Keep .instructions.md synchronized with architectural changes

## Development Workflow
1. **Understand the Change**: Read .instructions.md and relevant code sections
2. **Plan**: Identify files to modify and architectural impact
3. **Implement**: Make focused, atomic changes
4. **Test Locally**: Run `dotnet run` and verify UI behavior
5. **Verify**: Check that polling, event detection, and notifications work as expected

## Key Patterns to Apply

### Async/Await
- Always mark event handlers as `async void` or `async Task`
- Use `await` for HttpClient calls, file I/O, and async operations
- Disable UI controls before async operations, restore in finally blocks

### Event Detection
- Compare `MatchSnapshot` objects to detect changes
- Use event IDs for deduplication (HashSet<string> _sentEventIds)
- Return `IEnumerable<DetectedEvent>` from detection methods
- Filter by user preferences (NotifyKickoff, NotifyGoals, NotifyResults)

### Settings Management
- Always call `SaveSettings()` before async operations that depend on settings
- Persist to JSON using JsonSerializer.Serialize() with WriteIndented for readability
- Load settings on startup via `LoadSettings()`
- Reflect changes in UI via `ApplySettingsToUi()`

### UI Updates
- Add alerts to feed via `AddFeedItem(title, message)`
- Update status via `SetStatus(status, detail)`
- Maintain feed size limit (max 50 items)
- Use `UpdateFeedSummary()` after feed changes

### Error Handling
- Catch exceptions in try-catch blocks
- Log errors to feed and status display (never silent failures)
- Provide user-friendly error messages
- Restore UI state in finally blocks

## Code Style Checklist
- [ ] Private fields prefixed with underscore (`_fieldName`)
- [ ] Public properties use PascalCase
- [ ] Event handlers follow `ControlName_Action` pattern
- [ ] Sealed classes for records and internal types
- [ ] Target-typed new expressions where applicable
- [ ] Nullable reference types enabled (no null-forgiving operators unless justified)
- [ ] XAML uses consistent color palette and spacing
- [ ] Async methods properly use await and don't block UI

## Testing Checklist
- [ ] Run `dotnet run` and verify UI loads
- [ ] Provide valid API key and select favorite team
- [ ] Click "Send test notification" and verify toast appears
- [ ] Click "Check now" and verify API call succeeds
- [ ] Start/stop polling and verify timer behavior
- [ ] Modify settings and click "Save" to verify persistence
- [ ] Check that settings.json is created in %APPDATA%\WorldCupNotifier\
- [ ] Test error scenarios (invalid API key, no team selected)

## Prohibited Patterns
- ❌ Synchronous blocking calls in UI thread (use async/await)
- ❌ Hard-coded colors outside defined palette
- ❌ Nullable forgiving operators (`!`) without justification
- ❌ Silent exception swallowing (log to feed or status)
- ❌ Modifying _snapshots or _sentEventIds without deduplication logic
- ❌ Cross-platform code without platform checks
- ❌ Uninitialized ObservableCollection items

## File Ownership
- **MainWindow.xaml/cs**: UI layout, event handlers, polling logic, event detection
- **DesktopNotificationService.cs**: Windows native integration, COM interop, toast delivery
- **App.xaml/cs**: Application startup, service initialization
- **WorldCupNotifier.csproj**: Build configuration, dependencies

## When to Escalate
- Cross-platform support requirements (currently Windows-only)
- Major architectural refactoring (consider impact on settings persistence)
- New external API dependencies (evaluate licensing and rate limits)
- Performance concerns with large feed or frequent polling

## Success Metrics
- Code follows .instructions.md conventions
- All user-facing changes include error handling and status/feed feedback
- Async operations never block UI thread
- Settings persist correctly across app restarts
- Notifications deliver reliably (when enabled and events detected)
